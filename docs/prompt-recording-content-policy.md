# 提示词记录内容策略

提示词记录提供版本化的内容策略（`recording_policy.version = 1`）。所有内容开关统一使用“打开即保留”；请求头、请求正文、模型响应的总开关继续独立生效。

## 内容分类

| 开关 | 内容 |
| --- | --- |
| `user` | 用户输入的自然文本与代码 |
| `assistant` | 模型正文、最终回答、拒答 |
| `tool_call` | 工具名称、调用参数、调用关联信息 |
| `tool_result` | 工具读取和执行结果、自定义工具的业务 JSON |
| `system` | system 消息中未进一步分类的内容 |
| `developer` | developer 消息中未进一步分类的内容 |
| `instructions` | 协议顶层 instructions 字段中未进一步分类的内容 |
| `project` | 可识别的 AGENTS.md / CLAUDE.md 项目说明块 |
| `agent` | 可识别的代理身份、权限、协作模式说明 |
| `environment` | 可识别的运行环境说明块 |
| `skills` | 可识别的技能列表与技能说明块 |
| `reminder` | 可识别的系统提醒块 |
| `thinking` | 明确的 thinking / reasoning 字段及 analysis 通道 |
| `reasoning_summary` | 推理摘要与压缩摘要 |
| `tool_definition` | 工具定义、工具描述、additional_tools |
| `metadata` | 协议状态、用量、缓存控制及其他封套元数据 |

推荐策略仅开启前四项。协议中的密文、签名、图片、音频和其他二进制媒体始终剔除，不提供保留开关。图片生成结果、电脑工具截图等内置媒体也适用。自定义工具参数和结果中的同名业务字段不会被递归误删。

## 处理链路

1. 请求进入时捕获整份不可变配置快照，请求记录和对应响应共用这份策略。
2. 按协议结构识别消息和内容块，再拆分明确的项目、环境、技能等标记；普通用户引用、代码和未知文本保守保留。
3. 清除协议位置的密文与媒体，再按内容开关保留块。剔除内容仅累计类别、数量与字节数，不另存原文备份。
4. 请求保留最近 N 条用户与模型对话消息：包含可读正文的用户消息和模型回复各计 1 条，同一消息拆出的多个内容片段只计一次。工具调用、工具结果、思考、系统指令等辅助内容不占条数；保留对话区间内的辅助内容继续按内容开关处理。不截断工具业务 JSON 中名为 messages / input 的数组；工具结果保留可用的调用 ID 和工具名。
5. 保存 schema_version=2 的规范文档及本次策略快照，正文、详情和计数从同一份保留内容生成。
6. HTTP JSON 和 SSE 响应先规范化并合并增量，再执行相同分类与过滤。响应不使用请求的消息条数限制，按记录大小上限截断并标记。

OpenAI Chat、Responses、Claude Messages 和 Gemini 使用同一处理框架。WebSocket 保持逐轮请求记录，本次不扩展 WebSocket 响应采集。

## 配置、预览与兼容

管理页面始终展示 16 类内容开关。没有已保存策略时直接采用推荐策略；已有有效策略继续生效。“恢复推荐策略”仅重置草稿，点击保存后才替换当前策略。旧预设、AGENT、SKILLS 过滤开关及其执行链已移除，不再读取旧配置键；历史记录仅保留读取兼容，不重写或删除。

`POST /api/v1/admin/prompt-records/preview` 接收 `protocol`、JSON `body`、完整 `recording_policy` 和可选 `max_messages`，使用实际记录分析器返回保留内容和剔除统计，不保存记录或修改配置。预览请求上限为 1 MiB。

策略更新必须提供完整的 16 个布尔开关，拒绝未知类别、未知版本及已移除的旧过滤字段。已保存的策略若损坏，保留上一份有效快照；首次加载即损坏时暂停记录并报告配置错误，避免静默回退。

数据库迁移 `251_prompt_record_content_policy.sql` 仅增加策略快照和响应文档列。PostgreSQL 回归测试使用独立的 `prompt_content_policy_test` 数据库，追加并保留测试记录，不执行数据清理。
